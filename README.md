# SonicForge

**SonicForge** = Sonic（声音）+ Forge（锻造）。它不只是把声音「调大」，而是在系统音频链路上重新锻造一整套输出：自适应全局增益、多段均衡、低音补偿、三段响度均衡、限幅防削波、系统单声道。

解决手机（尤其小米 HyperOS）外放 / 媒体声音过小、推不动、一推就破音的问题。**增益会跟着系统音量走**：小音量时多补一点，音量推满时几乎让路，所以你可以在任何音量档位安心开增强，不用担心破音。

> **只支持 ROOT。** 普通 App 在 `audioSession = 0` 创建全局音效会被 AudioFlinger 以缺少 `MODIFY_AUDIO_ROUTING` 拒绝，HyperOS 上还有杜比 / 小米音效抢占 session 0 的链路 —— 免 ROOT 的路在真机上根本走不通。所以本应用把整条效果链搬进 **uid 0 的守护进程**，没有普通模式，也没有降级模式。

## 功能

- 🔊 **自适应全局增益**：`DynamicsProcessing` 的输入增益，挂在全局混音 `session 0`，对系统里所有 App 的媒体输出生效。补偿量随系统音量自动递减——小音量时最多 +4 dB（全链路硬上限），音量推满时**归零**（完全让路），越接近满音量越克制，从根上避免破音
- 🛡️ **限幅保护**：增益与均衡都在限幅器**之前**，峰值被压到 -1.5 dBFS 以下，不会削波爆音
- 🎛️ **均衡器**：频段数量由系统真实返回（10 / 8 / 6 / 5 / 3 自动适配），每段 ±6 dB，不是写死的十段
- 🎸 **低音补偿**：叠加在最低几个频段上（≤62Hz 权重 1.0，逐级衰减到 500Hz），并随系统音量一起收窄（满音量归零），因为低频最容易先失真
- 📊 **响度均衡**：三段多段压缩（200Hz / 2kHz / 20kHz 分频），把抖音、短视频、不同片源之间忽大忽小的音量拉平——小的抬起来、大的压下去，整体响度不变。分三段而不是单段，是为了避免低频触发压缩时的「抽气」感（bass pumping）。**默认随预设开启**：标准 50% / 人声 60% / 外放 40% / 夜间 70%
- 🎧 **只增强外放**：插耳机、连蓝牙、接 USB 声卡时自动暂停全部处理，耳机按设备原本的调音输出；拔掉后自动恢复
- 🎙️ **单声道**：直接写系统 `master_mono`（等同于「无障碍 → 单声道音频」），ROOT 下无需任何授权
- 🎼 **4 个预设**（小音量时的补偿上限）：标准增强 +3.3 dB / 人声增强 +2.7 dB / 外放最大 +4.0 dB / 夜间清晰 +2.0 dB，各自配一条按频段调过的均衡曲线——人声预设抬 250Hz~4kHz 的清晰度，外放预设抬 1kHz~8kHz 的穿透力，夜间预设压中低频、抬高频细节。**四个预设默认都开着响度均衡**（强度 40%~70%，夜间最高），切过去就直接生效，不用再手动拖
- 🧬 **协议版本自检**：状态文件带 `pv=` 版本号，App 启动时比对，发现跑的是装新 APK 之前拉起的旧守护进程就自动杀掉重拉——不会再出现「界面说响度均衡不可用，其实只是旧进程没这个字段」
- 🔓 **释放全局音效通道**：临时禁用杜比 / 小米音效包并重启 audioserver，避免它们和本应用抢 session 0 的音效槽位
- 🌙 **Material 3 明暗主题**、毛玻璃卡片、iOS 风格底部 Dock，单页面简洁 UI
- ✨ **克制的动效**：页面切换是方向感知的左右平移（点右边的页从右边滑入、点左边从左边滑入，旧页反向退场并叠淡），Dock 按下是图标微缩 + 胶囊泛色，没有水波纹方块
- 📵 **零危险权限**：不申请 `RECORD_AUDIO`、`MODIFY_AUDIO_SETTINGS`、`WRITE_SETTINGS`、`FOREGROUND_SERVICE`、`POST_NOTIFICATIONS`
- 🔕 **无常驻通知**：效果链由守护进程承载，App 可以退出、可以被划掉

## 安装与使用

从 [Releases](https://github.com/TWFU-wcy/SonicForge/releases) 下载 `SonicForge-<version>.apk` 安装，或本地构建后：

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

> 1.2.0 起包名从 `com.volumeboost.app` 改为 `com.sonicforge.app`，装过旧版的请先 `adb uninstall com.volumeboost.app`。

1. **先注入 ROOT**（临时 ROOT 工具如 HyperBreak，或已持久化的 KernelSU / Magisk），确认 `su` 可用
2. 打开 App，首次会弹 su 授权框，点「允许」
3. 选一个预设（推荐先用「标准增强」），打开「增强开关」
4. 播放任意音乐 / 视频，切到「调节」页拖「最大补偿」到合适位置——它调的是**上限**，实际生效值会随系统音量自动折算
5. 关闭开关即完全恢复原声

> 三个页面：**主页**（开关 + 当前最大补偿 / 实际补偿 + 预设场景）、**调节**（增益上限、10 段均衡器、低音增强、响度均衡）、**设置**（ROOT 状态、单声道、外观、音效诊断）。预设列表最后一项是「自定义」，点它会直接跳到「调节」页，把增益上限、均衡、低音全部调成自己想要的组合。

> 「调节」页的增益上限只有一个滑杆：**最大补偿**（小音量时的上限），范围 1.0~4.0 dB，顶端就是全链路硬上限，拖不出更高风险区。实际生效值会随系统音量自动折算，不需要手动再调；想知道当前折算到多少，主页主卡片里有两行——「当前最大补偿」和「实际补偿」。

> 临时 ROOT **重启即失效**。重启后重新注入 ROOT，再打开 App 点设置页的「重新检测」即可。

## ROOT 能力

| 能力 | 做法 | 说明 |
|---|---|---|
| **ROOT 全局音效** | 用 `su` 起一个 uid 0 的 `app_process` 守护进程（`RootDaemon`），在进程内把 `DynamicsProcessing` 挂到 session 0 | 普通 App 创建全局音效会被 AudioFlinger 以缺少 `MODIFY_AUDIO_ROUTING` 拒绝；uid 0 进程不受此限制，这是真机报「系统拒绝了音效创建」的正解 |
| **响度均衡** | `DynamicsProcessing` 的三段 MBC，挂在同一条链的 preEq 之后、limiter 之前 | 解决抖音 / 短视频「忽大忽小」：超过阈值的压下去、再加 makeup 补偿，动态范围收窄但整体响度不变；三段分频避免低频「抽气」 |
| **释放全局音效通道** | `pm disable-user --user 0 <厂商音效包>` + `setprop ctl.restart audioserver` | 杜比 / DTS / 小米音效会独占 session 0 的音效链路，禁掉后本应用的音效才能挂上去；可随时恢复 |

### 守护进程

- **位置**：`com.sonicforge.app.daemon.RootDaemon`，通过 `app_process` 以 uid 0 启动
- **启动命令**：`CLASSPATH=<apk> nohup setsid app_process /system/bin com.sonicforge.app.daemon.RootDaemon <cmd> <status> >> <log> 2>&1 &`
- **通信**：文件轮询，App 写 `files/sf_daemon.cmd`，守护进程每 250 ms 读一次，状态写 `files/sf_daemon.status`；音效参数（`active/boost/eq/bass/boost_min/leveler`）分行存放。状态文件里另有 `pv=`（协议版本）、`route=`（当前输出路由）与 `paused=`（是否因耳机暂停），App 每 2 秒读回来显示
- **心跳**：每 2 秒刷新一次状态文件的 `ts`；App 启动时读心跳，若发现它还在跑就自动接管界面状态（不会出现「显示已关闭但声音还在增强」）
- **协议版本**：状态文件第一行是 `pv=<版本号>`。装新 APK 后旧守护进程仍在跑（`setsid` 脱离的 uid 0 进程，覆盖安装不会杀掉它），它的状态缺新字段，界面会误报「响度均衡不可用 / 输出路由未知」。App 启动时比对 `pv`，对不上就先杀掉再重拉，保证跑的永远是当前这版代码
- **生命周期**：关闭开关写 `active=0`，守护进程自行释放音效并退出；配置文件被删除超过 5 秒也会自动退出
- **后台常驻**：用 `setsid` 脱离 App 会话，并把 `oom_score_adj` 调到 `-900`，App 退出 / 被划掉后仍继续工作；**因此不需要前台服务，也不显示常驻通知**
- **仍会失效的两种情况**：手动杀掉守护进程；手机重启（临时 ROOT 本身失效）
- **日志**：`files/sf_daemon.log`，也可在设置页「音效诊断」里查看尾部

## 原理与限制

- 效果链挂在 `audioSession = 0`（全局混音输出），对所有 App 的媒体流生效。
- 主链路是一条 `DynamicsProcessing`：**输入增益 → preEq → MBC（响度均衡）→ limiter → 输出**。顺序由系统保证，增益、均衡、压缩都在限幅器之前，所以推上去的峰值一定会被压回 0 dBFS 以下。
- 响度均衡用 `DynamicsProcessing` 的多段压缩（MBC）实现，不额外开第二条音效：三段分频 200Hz / 2kHz / 20kHz，阈值 -12 ~ -30 dBFS、压缩比 2:1 ~ 6:1 随强度线性变化，并带 makeup 补偿增益。强度为 0 时整段旁路，行为和没有这个功能一致。
- 建链时先尝试带 MBC 的配置，失败再退回不带 MBC 的同一条链（少数机型 DSP 不支持多段压缩）；能力在诊断里以 `mbc=1/0` 报告。
- 若机型拒绝创建 `DynamicsProcessing`（频段数不支持），守护进程会按 10 / 8 / 6 / 5 / 3 逐个重试；全部失败才退到单个 `LoudnessEnhancer`（无限幅，增益上限压到 +4 dB），并在诊断里写明。
- 都失败时界面显示「系统拒绝了音效创建」，不会假装成功。
- 均衡器频段数量与中心频率全部来自系统返回，界面按真实频段渲染；当前模式不支持的控件自动置灰。
- 单声道写系统设置 `master_mono`，ROOT 下直接写，不需要「修改系统设置」权限。
- 不申请 `RECORD_AUDIO`，不捕获任何音频数据，纯输出侧处理。
- **只对扬声器外放生效**：守护进程每 1.2 秒读一次 `dumpsys media.audio_flinger` 的 `Output devices`，一旦发现当前输出不是内置扬声器 / 听筒（有线耳机、USB 耳机、蓝牙 A2DP、BLE、助听器、HDMI 等），立即释放整条音效链，让耳机按设备原本的调音输出；拔掉耳机切回扬声器后自动重建链路恢复增强。读不到路由信息时保守放行（当作扬声器处理），不会因为一次 `dumpsys` 超时就把增强关掉。
- **自适应增益**：软件补偿不是固定值，而是跟着系统媒体音量走。设系统音量为 v（0~1）、补偿上限为 max、满音量保留值为 min，补偿量按 `min + (max - min) × (1 - v^p)` 计算——音量低时接近上限，音量越高越快收窄，满音量时**精确落在 0 dB**（min = 0）。指数 p 不是固定的 1.6，而是由「斜率预算」反推：`p = clamp(560 / (max - min), 0.3, 1.6)`。
- **为什么必须这么算（单调性）**：系统音量本身在衰减信号，按线性幅度折算，音量从 v 涨到 v + Δ 时输出约涨 `8.686 / v × Δ` dB，在满音量处最慢（8.686 dB 每单位 v）。补偿曲线只要降得比这更快，总音量就会倒挂——「音量键按上去反而变小」，90% / 95% 档比 100% 档还响。约束 `(max - min) × p ≤ 预算` 保证补偿的下降速度永远不超过系统音量的上升速度，于是「原始音量 + 补偿」严格单调递增，100% 档永远是全曲线最响的一档。
- **预算怎么分**：主增益 560 + 低音补偿 180 = 740，小于系统斜率 868，留 14.8% 余量。低音补偿最终折算成 dB 叠在主增益上（强度 1000 = 最低频段 +6 dB），所以两者必须共享同一份预算，不能各算各的。余量不是浪费——下发值按 1/100 dB 取整，每档最多带入 ±0.016 dB 的量化误差；音量档位越细，相邻两档的真实涨幅越小，余量不足时取整误差就会把两档顺序翻过来。留到 740 之后，上限 1~4 dB 逐毫贝尔 × 低音 0~1000 逐档 × 15 / 16 / 25 / 30 / 50 / 100 档音量（覆盖全部真机档数）实测 0 倒挂。上限 ≤ 3.5 dB 时 p 被 1.6 封顶，曲线形状和以前完全一致。
- **百分比的含义**：主页显示的 `+26%` 不是电压倍数，而是**感知响度**（sone 标度）：`(2^(dB/10) - 1) × 100`。+2 dB ≈ +15%、+4 dB ≈ +32%，和「听起来大了多少」一致；下面一行同时标注等效 dB，两种口径都看得到。
- **预设的均衡曲线**按频段做过针对性调整，而不是简单拉平：人声增强在 250Hz~4kHz 抬 +1.2~+3.6 dB 并压掉 31Hz 与 16kHz 的浑浊与齿音；外放最大抬 1kHz~8kHz 增加穿透力、压 16kHz 减少刺耳；夜间清晰压 250~500Hz 的轰隆感、抬 2kHz~8kHz 的细节。
- 长期高增益 + 高音量有损扬声器风险，建议把系统媒体音量控制在 80% 以下使用。
- App 本身不含任何提权或漏洞利用代码，只在系统已经提供 `su` 时使用它。

## 常见问题

**主页显示「需要 ROOT 才能开启」**
`su` 没拿到。确认临时 ROOT 已注入，打开 App 后点设置页「重新检测」；KernelSU 里也要允许本应用。

**设置页显示「需要 ROOT 权限才能工作」**
同上。可先到 KernelSU 管理器的「超级用户」列表里手动授予 `com.sonicforge.app`。

**开关能打开，但没声音变化**
到设置页点「音效诊断」，看 `【ROOT 守护进程】` 段：`mode=FULL` 表示链路正常；`mode=DEGRADED` 表示只挂上了 LoudnessEnhancer；`error` 行会写明失败原因。把这段文本贴到 issue 里即可定位。

**插上耳机后增强好像没了**
这是预期行为。本应用只增强扬声器外放：守护进程每 1.2 秒检查一次当前输出设备，发现是耳机 / 蓝牙 / USB 声卡时会释放整条音效链，让耳机按设备原本的调音输出。拔掉耳机后 1 秒多就会自动恢复，主页副标题会显示「已连接耳机 · 增强已暂停」。

**把系统音量推到最大后，增强还有多少**
只剩 **0 dB**（主页显示 `+0%`，即完全让路）。这是刻意设计的：满音量时扬声器已经接近物理极限，实测再叠 +1.2 dB 就会破音，所以软件补偿在音量升高的过程中逐渐让路，到满音量时彻底退出。想要更响，请把音量调低一些，让软件补偿有空间发挥作用。

**主页的 `+33%` 是什么意思**
是感知响度的提升幅度（sone 标度），不是电压或功率倍数。主卡片里「实际补偿」一行同时给出百分比与等效 dB。这个数值会随系统音量实时变化：音量越大，数字越小。

**预设默认带响度均衡，会和我手动调冲突吗**
不会。选中预设时响度均衡会被设成该预设的默认强度（标准 50% / 人声 60% / 外放 40% / 夜间 70%），之后你在「调节」页手动拖动的值会一直保留——只有在重新点选某个预设时才会被覆盖一次。

**重启后失效**
临时 ROOT 重启即失效，属预期行为。持久化 ROOT（KernelSU / Magisk 模块）可做到开机自启。
